# RaagMusicGen: Music Generation Logic and Technical Overview

It leverages predefined raag structures and a Python-based toolchain to produce tunes, complete with MIDI audio and Western sheet music annotated with Indian notes. This document is organized into two sections – **Logic** (how the musical rules and generation work) and **Tech** (the software stack and data handling) – to explain how RaagMusicGen generates music.

## Logic

The RaagMusicGen logic encodes principles of Hindustani classical music (raags) and uses them to algorithmically compose melodies. Key components of this logic include classes that define raag scales and motifs, and a generator that builds a tune following those rules:

- **`BaseRaag.py`** – Defines the core properties of a raag, such as the ascending scale (*Arohana*), descending scale (*Avarohana*), and a characteristic phrase (*Pakad*). These properties list which swaras (notes) occur in the raag and in what order for ascent/descent. For example, `BaseRaag` might have attributes for `aroha` and `avaroha` (each a list of swaras) and `pakad` (a list or pattern of swaras defining the raag’s signature phrase). This base class provides a framework to enforce raag rules by exposing which notes are allowed when moving up or down the melody.

- **`Yaman.py`** and **`Durga.py`** – Concrete raag definition classes that subclass `BaseRaag` to implement specific raags. For instance, `Yaman` defines its Arohana as **Ni–Re–Ga–Ma♯–Dha–Ni–Sa** and Avarohana as **Sa–Ni–Dha–Pa–Ma♯–Ga–Re–Sa** (using a teevra Ma, i.e. sharp Ma). In contrast, `Durga` is a pentatonic raag (audav jati) that defines Arohana **Sa–Re–Ma–Pa–Dha–Sa** and Avarohana **Sa–Dha–Pa–Ma–Re–Sa**, omitting Ga and Ni. Each raag subclass also specifies a Pakad: e.g. Yaman’s pakad might include the phrase *Ni–Re–Ga* (highlighting the ni->Re->Ga movement), and Durga’s pakad is given as *“Re Ma Pa Dha, Ma Re”*. These subclasses typically initialize the base class with the raag’s specific scale sequences and pakad. By encapsulating raag rules in these classes, the rest of the system can generate music that adheres to the correct notes and phrases for that raag.

- **`RaagGen.py`** – The orchestration logic that uses the raag definitions to create a tune. This module (or class) is responsible for constructing a melodic sequence following the chosen raag’s rules. It will instantiate the selected `BaseRaag` subclass (e.g. a `Yaman` or `Durga` object) and then generate a sequence of swaras for the melody. The **RaagGen** logic ensures that any upward-moving series of notes follows the raag’s Arohana order and any downward series follows the Avarohana. In practice, this means if the melody is ascending from a given note, the next note must be the next higher swara as defined in the raag’s scale (skipping any notes not in the raag). Likewise, descending phrases pick the next lower swara according to that raag’s descending scale. By consulting the raag object’s allowed notes, the generator avoids any out-of-scale notes or forbidden note sequences.

**Swara selection and raag rules:** The melody generation often works as an algorithm that steps through notes with regard to raag constraints. For example, `RaagGen.py` might maintain a current note and a current direction (ascending or descending) and choose the next note by looking up the current note’s position in the raag’s scale. If moving upward, the code selects the following note in the raag’s Arohana list; if moving downward, it selects the next note in the Avarohana list. The generator can also decide when to change direction (ascending vs. descending) to create a musically pleasing contour. Importantly, it may incorporate the **pakad** motif deliberately into the melody – for instance, by injecting the pakad sequence at the beginning or as a recurring theme – to ensure the tune clearly evokes the chosen raag. As a result, the generated tune is not just random notes from the scale, but a sequence that respects the typical phrases and motion of the raag. The logic might also ensure the melody resolves on the tonic (*Sa*) or emphasizes important notes (like vadi/samvadi) to give it a coherent raag feel. Overall, this rule-based selection of swaras means the output melody follows the traditional structure of the raag (for example, never using a note that isn’t in the raag’s scale, and adhering to the raag’s permitted note order when ascending or descending).

## Tech

The technical implementation of RaagMusicGen combines several Python libraries and modules to handle music data, convert between musical representations, and provide outputs (audio and notation) to the user. This section covers the software stack, data mappings, and the overall architecture including the user interface.

**Python libraries and music data format:** RaagMusicGen is built with Python, using specialized libraries for MIDI and music notation. The **`mido`** library is used for MIDI file creation and playback. Mido provides an easy way to construct MIDI tracks, add notes, and save them as standard MIDI files (it allows one to read, write, and even play back MIDI data in Python). Using mido, the program creates a `MidiFile` with one or more tracks – for example, one track for the melody and maybe another for a drone or chord accompaniment. It appends MIDI messages for note-on and note-off events according to the generated melody, and sets the instrument sound by sending a program change message (for instance, selecting a Piano or Flute sound). Once the sequence is built, it calls `mid.save("output.mid")` to produce a MIDI file that can be played or downloaded.

Another key library is **`music21`**, which is a comprehensive toolkit for music analysis and generation developed at MIT. RaagMusicGen uses music21 to handle music notation and MusicXML output. While MIDI is great for playback, **MusicXML** is a standardized format for sheet music that captures detailed notation (pitch, rhythm, and markings) better suited for reading and printing. Using music21, the code translates the generated melody into a score: it creates music21 Note objects for each swara (assigning the corresponding Western pitch and duration), possibly adds them to a Part or Stream, and attaches metadata like time signature or tempo as needed. Crucially, the Indian swara names can be added as lyrics or annotations to each note in the music21 score, so that when exported, the MusicXML contains those syllables. Finally, the program writes out the notation as a MusicXML file (e.g. `stream.write('musicxml', 'output.musicxml')`). This file can be opened in notation software or rendered in the web interface for the user to see the sheet music.

**Mapping Indian swaras to Western notes:** A fundamental part of the tech stack is converting Indian note names (Sa, Re, Ga, Ma, Pa, Dha, Ni) into Western pitches (like C, D, E, F, G, A, B) so that MIDI and MusicXML can be generated. RaagMusicGen likely uses a defined mapping based on a chosen root note (typically Sa is treated as C in Western notation for simplicity). In code, the raag definitions might list swaras, which the program then translates to MIDI note numbers or music21 pitch names. For example, if the base tonic **Sa** is mapped to C4 (middle C), then **Re** becomes D, **Ga** becomes E (if shuddh Ga), **Ma** becomes F, **Pa** G, **Dha** A, **Ni** B in that scale. Raag-specific alterations are accounted for: in **Yaman**, the Ma is teevra (sharp), so the mapping uses F♯ for Ma♯. In **Durga**, Ga and Ni are omitted entirely, so those swaras simply never appear in the generated notes. The software might implement this mapping by a dictionary or function – for instance, a function `swaratoNote(swara)` that returns the correct MIDI pitch or music21 note given the swara and the raag context. It likely handles **komal** (flat) swaras as well, e.g. if a raag had a komal Re, the mapping would yield a D♭. In summary, this translation layer ensures that when the code selects swaras from the raag’s scale, they are realized as the proper Western notes for output.

**Instrument selection (`Instrument.py`):** This module handles the choice of instrument sound for the generated music. Instruments in MIDI are identified by program numbers (the General MIDI standard). The `Instrument.py` file probably defines a mapping or class that maps human-readable instrument names to MIDI program numbers. For example, “Piano” might correspond to program number 0, which is the Acoustic Grand Piano in General MIDI. A choice like “Flute” would use program 73, the MIDI patch for a flute sound. When the user selects an instrument in the front-end, the program looks up the corresponding MIDI program and inserts a MIDI *program change* message at the start of the track (so that the MIDI playback uses that instrument sound). This way, the same melody can be rendered with different timbres (e.g. piano, flute, violin, etc.) without altering the notes. The Instrument module centralizes these mappings and possibly could be extended to support more instruments or custom sound fonts in the future.

**Harmony and drone generation (`ChordGen.py`):** In addition to the main melody, RaagMusicGen can generate harmonic support or a drone using the `ChordGen.py` module. Indian classical music often uses a drone (typically the **Tanpura** playing the tonic and fifth) rather than chord progressions, but this project might implement a simple harmony to enrich the sound. The `ChordGen.py` likely contains logic to create a secondary track or background notes that complement the melody. One approach is to continuously play the root note (Sa) and fifth (Pa) as a drone chord – for example, sustaining a low Sa and Pa in the background to establish the tonal center. Another approach could be Western-style chords: since raag scales can be treated as modes, the module might build chords (triads or dyads) using only notes from the raag’s scale, thus not breaking the raag character. For instance, for Raag Yaman (which is similar to a Lydian mode), it could use chords like C major or G major (chords that use notes within Yaman’s scale). The `ChordGen` might provide a method to generate a sequence of chord changes or a repeating pattern that aligns with the melody’s rhythm. These chords or drone notes are then added via mido to the MIDI file (often on a separate track or channel) and to the music21 score (perhaps as a lower staff or as layered notes). The result is that the output music can have a richer texture: the melody line accompanied by harmonic support. In the sheet music, this might appear as chords or a bass line, and in the audio it gives a fuller sound.
